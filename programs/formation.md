## 题目描述

> 出题助教：刘治元

蚂蚁大学即将迎来110周年校庆，学校计划调动全校摆一个校庆开场阵型，以便通过无人（蚁）机俯拍，感受蚂大学子的风采。“什么年代还摆传统阵型？”作为计算机院士的蚂蚁校长为了让学生感受到趣味的同时不失阵型的气势，决定来点新花样。据校史记载，它们列阵的方式后来被称为[Rule 110](https://en.wikipedia.org/wiki/Rule_110)。

具体操作如下：

假设全校蚂蚁恰能站成一个 $m$ 排 $n$ 列的矩阵，每只蚂蚁只有两种动作：站立、蹲下，分别用`1`和`0`表示。

最初，第 $ 1$ 排的蚂蚁任意地站立或蹲下。

对于后面每一排，每一只蚂蚁的动作将由其**正前方**的蚂蚁以及**和正前方蚂蚁左右相邻**的蚂蚁决定。具体规则如下：

$1\ 1\ 1 \rightarrow 0$

$1\ 1\ 0 \rightarrow 1$

$1\ 0\ 1 \rightarrow 1$

$1\ 0\ 0 \rightarrow 0$

$0\ 1\ 1 \rightarrow 1$

$0\ 1\ 0 \rightarrow 1$

$0\ 0\ 1 \rightarrow 1$

$0\ 0\ 0 \rightarrow 0$

其中右边的数字表示后排一只蚂蚁的动作，左边的数字表示前排从左到右对应三只蚂蚁的动作。若对应的不足三只蚂蚁，每个空缺位置仍视为一只**蹲下**的蚂蚁。

外校的Fradow同学想在网上瞻仰这个壮观的阵型！但因为手机流量不足，图片刚加载出第一排就卡住了……你能用字符向他展示省流版的剩余阵型吗？

## 输入格式

输入包含两行。

第一行为两个整数 $m$, $n$；第二行是长度为$n$的字符串，表示第一排蚂蚁的动作情况，其中`1`表示起立，`0`表示蹲下。

## 输出格式

输出最终除第一排外的剩余阵型，共 **$m-1$** 行，每行 $n$ 个字符。

## 样例

**输入**

``` text
10 10
0000000010
```

**输出**

``` text
0000000110
0000001110
0000011010
0000111110
0001100010
0011100110
0110101110
1111111010
1000001110
```

## 提示

#### 输入规定

对于所有的数据有 $1\le m, n \leq 2000$。

第二行输入的字符只有可能包含`1`和`0`。

#### 拓展阅读（过了再看）

> 搞什么嘛，这个题好像还挺简单的……但最核心的逻辑判断部分似乎有点长。有没有办法实现得更优雅呢？

说的很对！本题蚂蚁的动作由其他3只蚂蚁决定，每一只有2种状态，共有 $ 2^3=8$ 种可能，因此有8条规则。从数学的角度看，每条规则可以视作一个函数关系，三个自变量（输入）可确定一个因变量（输出），如 $f(1, 1, 0) = 1$。由于规则的设定是任意的，不必存在一个通用的表达式，你因此需要做很多次条件判断。倘若改变题目，动作由其他更多蚂蚁决定，每只蚂蚁的动作也增多，条件判断便会更复杂，代码随之变得更冗长。

我们可以发现，对于每组规则，仅是输入和输出不同，但条件判断的模式是相同的，即三个输入通过同种运算得到一个输出。这导致的问题是，如果有一天我们被要求改变这种模式，我们就需要改变代码中每一处使用过这种模式的地方，具体在这题是8次。但在未来的工程实践中，同一个模式的出现次数远不止这个数字。

如果我们能用代码将这种模式封装起来，只维护1段有关模式的代码，其余地方只需考虑输入和输出，岂不妙哉？

恭喜你发现了封装的本质！在编程中恰当地使用封装，常常会让代码高效而优雅，更重要的是代码会变得易于修改。最常见的一种封装方式是接下来课上将会学到的函数，而今天介绍的则是原理完全不同的另一事物——宏（macro），对应教材的预处理器章节 $\rm P_{246} \sim P_{271}$。

你或许已经在代码中使用过宏。开较大的数组时，你可能会将数组大小封装，以便修改：

```
#define SIZE 1000007
int nums[SIZE];
```

你在代码中使用了一些神奇的数字（magic numbers），为了让别人也能看懂你的代码：

```
#define EOF -1
#define INT_MIN -2147483648
#define MY_TA "Sakiyary"
#define MY_BIRTHDAY 1919810
#define THE_ANSWER_TO_UNIVERSE 42
```

编写与这些值有关的代码时，你不再需要在每一处都填上具体的值，而是用更易读的别名代替。如果某一天这些值发生了改变，你也只需修改宏定义即可。那么这和本题的逻辑判断有何关联呢？

实际上，宏是可以带参数的，编译器会在预处理时将参数进行对应的替换。（下列代码中的反斜线\被称为续行符）

```
#define AUGMENT(x) ((x) + 1)
#define MAX(x, y) ((x) > (y) ? (x) : (y))
#define MAX_AND_AUGMENT(x, y) (AUGMENT(MAX(x, y)))
#define SING_IF_YOU_LIKE(condition) if (condition) { \
  printf("mymymymyqtddt\n");                         \
}

/* below are the simplest applications */

int two = AUGMENT(1);
int six = MAX(5, 6);
int one = MAX_AND_AUGMENT(-2, 0);
SING_IF_YOU_LIKE(one)
```

以你现有的知识，已经可以开始学习利用宏。若你时间充足，可以仔细阅读教材，尝试理解宏的真正原理后再去使用！如何知道自己有没有理解？尝试回答下列问题：

1. 为什么上面的宏定义中要套很多很多的括号？
2. 为什么最后一行使用SING_IF_YOU_LIKE时结尾无分号？

回到本题，你能利用宏定义将规则封装，使得后排蚂蚁站立的条件变成下面这个式子吗？

`f(1, 1, 0) || f(1, 0, 1) || f(0, 1, 1) || f(0, 1, 0) || f(0, 0, 1)`
